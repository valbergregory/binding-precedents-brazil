All entries were probed from the research machine on 2026-09-04/05 with plain HTTP requests
and, where a file was downloadable, by downloading and parsing a sample. Probe logs:
`logs/source_checks/`. Machine-readable version: `config/sources.yml`.

Legend for **Access**: `ok` = usable programmatically now; `partial` = reachable but incomplete
for our purpose; `manual` = usable only through a browser UI; `blocked` = not usable.

## Sources considered and rejected for bulk use

| Source | Why not |
|--------|---------|
| State and federal appellate courts' jurisprudence search pages (TJSP, TJRS, TRF4 and others) | Web forms for humans; no documented bulk endpoints; scraping at scale would violate the "no circumvention" rule and their terms. Not verified individually in Phase 0 because the design does not depend on them. |
| TJDFT `jurisdf` API | Reported as an open REST API for a single court; not probed in Phase 0. Could serve a **single-court robustness check** in a later phase, never the main design. |
| STF jurisprudence search (`jurisprudencia.stf.jus.br`) | Answers HTTP 202 challenge pages to non-browser clients. Manual only. |
| Base dos Dados (Corte Aberta mirror) | Requires a Google Cloud account and BigQuery; acceptable as a secondary channel for the STF theme registry, to be decided in Phase 1. |
